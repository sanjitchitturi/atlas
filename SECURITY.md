# Security reporting

Do not post credentials, private data, or exploitable vulnerability details in public issues.
Use GitHub's **Report a vulnerability** option under the repository's Security tab when
available. Otherwise use a private contact method listed on GitHub before sharing
sensitive details. If no private channel is available,
open an issue requesting one without describing the vulnerability.

Include the affected revision, impact, prerequisites, and a minimal reproduction using
synthetic data. Never include working credentials or another person's data.

Security fixes target the current default branch; no older release support or response-time
guarantee is offered. Consult the README for project-specific deployment constraints.
Dependency scanning and CI do not constitute a security audit.
